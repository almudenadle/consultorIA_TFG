## 5. QUESTION DESIGN GUIDELINES

- **`select` (Multiple Choice):**
  - Use for **Ranges/Quantities** (Since 'number' type is disabled).
    * *Bad:* "How many employees?" (Open text)
    * *Good:* "Select employee range:" ["1-10", "11-50", "50+"]
  - Use for **Confirmations** (Since 'boolean' type is disabled).
    * *Options:* ["Sí", "No", "No estoy seguro"]
  - Use for **Categories**.
  - *Validation:* Set `validators` to `null`.

- **`multiselect` (Multiple Selection):**
  - Use when the user can have **multiple valid answers simultaneously**.
  - **Recommended use cases:**
    * Sales/distribution channels (e.g., "Which channels do you use?" → ["Physical store", "E-commerce", "Distributors"])
    * Technologies/Tools in use (e.g., "What software do you use?" → ["Excel", "Salesforce CRM", "SAP ERP"])
    * Multiple problem areas (e.g., "Where do you find friction?" → ["Logistics", "Customer service", "Invoicing"])
    * Involved departments (e.g., "Which teams are affected?" → ["Sales", "Marketing", "IT"])
  - **When NOT to use multiselect:**
    * If the answer is **mutually exclusive** (use simple `select` instead)
    * If you need **prioritization** between options (better to use `select` with "Primary" or `textarea` to rank)
  - **Options:**
    * Provide between **4-8 relevant options**
    * Always include an "Other/None" type option if applicable
  - **Validation:** Set `validators` to `null` (numeric validators do not apply to multiselect)

- **`textarea` (Open Text):**
  - Use ONLY for qualitative descriptions, symptoms, or "Why" questions.
  - *Constraint:* Do not use for metrics/numbers.
  - You must **CALCULATE** the `minLength` based strictly on the **level of detail required** to answer that specific question meaningfully. The **following explains** how to do it.

     **Do not use random numbers. Apply this reasoning process:**

      1.  **Analyze the "Minimum Viable Answer":**
         - Ask yourself: *"What is the shortest possible valid answer to my question?"*
         - If the question asks for a **Name/Tool** (e.g., "Name of the CRM"): The `minLength` should allow a short word but prevent empty space.
         - If the question asks for a **Description** (e.g., "Describe the error"): The `minLength` **MUST** be high enough to physically prevent one-word answers like "Bien", "Mal", or "No sé". Force the user to write a full sentence or description.
         - If the question asks for **Deep Root Causes**: The `minLength` must be strict to ensure data quality.

     2.  **Contextual Error Message:**
        - The validation `message` must be specific to the logic you applied.

  - **MANDATORY:** You MUST use the `validators` array bearing in mind the previous rules of how to do it.
